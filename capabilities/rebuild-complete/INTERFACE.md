# Complete rebuild interface, version 1 draft

## Named user job

Given an explicitly authorized direction-change rebuild and target project,
construct a target-native implementation line from an empty or pinned
historical baseline, selectively transfer valuable behavior and knowledge, and
prepare or execute only the authorized portion of transition and retirement.

## Inputs

- Target project and applicable owner guidance.
- Explicit implementation authority.
- Accepted target direction or enough authority to create and implement a
  bounded plan.
- Source, evidence, compatibility, and target baselines.
- Repository and operational access needed for the requested scope.

## Output contract

- Preserve the active checkout, unrelated work, and immutable history.
- Use an isolated target line at a pinned source baseline.
- Establish target boundaries and a working target-native vertical before
  broad legacy import.
- Admit old assets through explicit implementation and knowledge dispositions.
- Verify target fit separately from required compatibility and intentional
  divergence.
- Detect durable forbidden legacy dependencies where practical.
- Record actual implementation, evidence, transition state, and residual
  limits.

## Exclusions

This interface does not promise destructive rewind, silent history rewriting,
automatic behavior parity, deployment, public release, production cutover,
irreversible data mutation, consumer migration, old-system deletion, or owner
acceptance without corresponding authorization and evidence.

## Compatibility

Version 1 freezes isolated non-destructive rebuilding, intent-first target
derivation, asset-level re-entry, separate target and compatibility evidence,
and explicit transition authority. Exact language, framework, and repository
layout remain target-owned.
